# 剧集入库合并通知功能

## 功能概述

实现了剧集入库的**防刷屏合并通知**机制。当连续入库同一剧集的多集时，会自动聚合等待 60 秒后发送合并通知，而不是每集单独发送一条通知。

## 技术实现

### 1. 每个 Key 独立的定时器机制

```go
type EpisodeAggregation struct {
    // ... 其他字段
    timer *time.Timer  // 每个 Key 独立的定时器
    mu    sync.Mutex   // 每个 Key 独立的锁
}
```

**核心改进**：
- 之前：使用全局定时器，任何新剧集都会重置所有聚合的定时器
- 现在：每个 `seriesName_season` Key 有独立的定时器，互不影响

### 2. Debounce 防抖逻辑

```
收到 Episode 1 → 创建聚合，启动 60s 定时器
收到 Episode 2 → 加入队列，重置 60s 定时器
收到 Episode 3 → 加入队列，重置 60s 定时器
...
60s 无新数据 → 触发发送合并通知
```

### 3. 智能集数格式化

- **连续集数**：`E01-E05`、`E08-E12`
- **不连续集数**：`E01, E03, E05, E08-E10`
- **单集**：`E05`

示例：`神墓 S01 E01-E05, E08-E12` (共8集)

### 4. 文件大小和数量累加

- 每收到一集，累加其 `FileSize` 和 `FileCount`
- 最终通知显示**总大小**和**总文件数**

## 通知格式示例

### 详细模式
```
✅ 入库成功：神墓 (2025) S01 E01-E10
───────────────────

🎬 名称：神墓 (2025) S01 E01-E10
🏷️ 类别：国产剧
💎 质量：WEB-DL 1080p
📦 总大小：8.52 GB
📁 文件数量：10个
```

### 简洁模式
```
📺 入库通知

《神墓》 (2025) 第1季 E01-E10
💎 WEB-DL 1080p · 📦 8.52 GB
🕒 19:30
```

## 配置参数

- **聚合延迟**：60 秒（可在 `WebhookService.aggregationDelay` 修改）
- **清理机制**：定时器触发后自动从内存删除

## 并发安全

- 使用 `sync.RWMutex` 保护聚合 Map
- 每个 `EpisodeAggregation` 使用独立的 `sync.Mutex`
- 防止数据竞争和内存泄漏

## 日志输出

```
[入库聚合] 创建新聚合: 神墓 S01, 延迟 1m0s 后发送
[入库聚合] 添加集数: 神墓 S01E01 (当前共1集, 总大小:852MB), 重置定时器 1m0s
[入库聚合] 添加集数: 神墓 S01E02 (当前共2集, 总大小:1.70GB), 重置定时器 1m0s
...
[入库] 神墓 S01 E01-E10 (10集, 总大小:8.52GB)
```

## 代码改动位置

- `internal/services/webhook.go`
  - `EpisodeAggregation` 结构：添加 `timer` 和 `mu` 字段
  - `WebhookService` 结构：移除全局定时器，添加 `aggregationDelay`
  - `aggregateEpisode()` 函数：重写，实现独立定时器
  - `flushSingleAggregation()` 函数：新增，处理单个 Key 的发送
  - `flushEpisodeAggregation()` 函数：修改，兼容新结构

## 测试建议

1. **单集入库**：60秒后收到单集通知
2. **连续入库**：一次性入库整季，只收到一条合并通知
3. **分批入库**：间隔小于 60 秒，会合并；间隔大于 60 秒，分多条发送
4. **并发入库**：多剧集同时入库，各自独立聚合，互不影响
